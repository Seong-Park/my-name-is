# 나의 이름은 웹 앱

Figma 4개 페이지의 토큰·공통 컴포넌트·패턴·41개 화면/상태 예시를 하나의 입력·결과 흐름으로 조합한 Next.js 앱입니다. 시스템 글꼴을 사용합니다.

## 실행

저장소 루트 `C:\workspace\my-name-is`에서 실행합니다.

```powershell
pnpm install
pnpm --filter @my-name-is/name-web dev
```

- 서비스: http://127.0.0.1:3100
- 개발 시연: http://127.0.0.1:3100/dev
- 검증: `pnpm --filter @my-name-is/name-web test`, `typecheck`, `build`

`/dev`는 개발 모드에만 존재합니다. 프로덕션에서는 404입니다. 상단 개발 패널에서 후보 수, 보류, 분석 실패, 회상문 실패/중단/불확실, 저장·복사 실패를 선택합니다. 응답 대기는 ‘대기 요청 완료’를 눌러 종료하며 자동 타이머로 결과를 만들지 않습니다. 입력은 직접 넣습니다. 시연의 한자·이름·이야기는 실제 추천이나 AI 출력이 아닙니다.

## 환경 변수

`apps/name-web/.env.local`에 아래 이름으로 키를 넣습니다. 파일은 이미 준비되어 있으며 기존 키를 덮어쓰지 않습니다.

```dotenv
DEEPSEEK_API_KEY=
DATABASE_URL=
NAME_RECEIPT_SECRET=
```

루트 `.gitignore`의 `.env.*` 규칙에 포함됩니다. 값이 없는 `.env.example`만 공유합니다. AI 키에 `NEXT_PUBLIC_` 접두사를 붙이지 않습니다. 키 파일을 출력하거나 클라이언트로 전달하지 않습니다.

개발 DB는 Supabase PostgreSQL을 사용하기로 선택했습니다. `DATABASE_URL`은 서버 전용 PostgreSQL 연결 문자열입니다. Supabase URL/anon key로 대체하지 않습니다. `NAME_RECEIPT_SECRET`은 별도로 생성한 32바이트 난수를 64자리 16진수로 저장하는 서버 서명 키이며 DeepSeek 키를 재사용하지 않습니다.

선택 설정:

- `NAME_WEB_ORIGIN`: 요청을 허용할 서비스 origin. 기본값 `http://127.0.0.1:3100`. 다른 호스트/포트를 사용할 때 변경합니다.
- `NEXT_PUBLIC_KAKAO_JS_KEY`: Kakao JavaScript 공개 키. 앱과 허용 도메인을 설정한 후 사용합니다. 미설정/SDK 실패 시 시작 URL 복사로 이어집니다.

**지원 구조에서는 실제 추천과 유료 DeepSeek 호출이 실행됩니다.** 원국 계산과 서명 영수증, 토큰 검사·원장 예약·공급자 전송·정산을 연결했습니다. 현재 추천 범위는 [楠曰 곡직의 제한된 구조군](../../docs/research/2026-10-01-quzhi-adopted-scope.md)의 목 극대화형과 [겨울 목 조건군](../../docs/research/2026-10-03-winter-wood-boundary.md)의 화 균형형입니다. 겨울 조건군에서 모든 한자를 선택하고 이름 부분이 검토된 화 오행으로만 구성되면 잘 맞는 이름으로 평가합니다. 다른 오행 역할과 미지원 구조는 보류합니다. 겨울 조건군은 실제 날짜 역법 회귀와 브라우저 입력→평가→균형 추천·복원을 확인했습니다. 해당 후보의 초기 회상문은 JSON 형식에 실패했으나, 닫기 지시를 보강한 v3에서 실제 생성·저장·복원을 확인했습니다. 표본이 작아 생성 안정성을 보장하지는 않습니다. 이 해석은 고전 한 저자의 설명을 서비스 규칙으로 옮긴 것으로, 과학적 측정이나 학파 공통 결론이 아닙니다.

후속 개발 검증에서는 Supabase 원장을 적용하고 세 가지 문장 검증 자료로 DeepSeek를 총 4회 호출했습니다(첫 자료의 수동 재시도 1회 포함). 비용·실패·성공 결과는 [별도 검증 기록](../../docs/verification/2026-10-01-deepseek-calibration.md)에 있으며 실제 출생정보 추천의 성공 증거는 아닙니다. 유료 호출 기록이 있으므로 빈 원장 전용 `test-ledger.ts`를 이 DB에 다시 실행하거나 호출 기록을 지우지 않습니다.

공식 tokenizer 자료는 Git 제외 캐시에 둡니다. 새 개발 환경에서는 테스트·빌드 전에 앱 디렉터리에서 `./scripts/setup-tokenizer.ps1`을 실행합니다. 고정 SHA-256이 달라지면 교체하지 않고 중단합니다. Python 원격 코드를 실행하지 않습니다. 빌드는 이 자료를 서버 assets로 추적합니다.

## 실제 연결과 교체 지점

| 경로 | 현재 구현 | 남은 작업 |
| --- | --- | --- |
| `GET /api/name/v1/config` | 기존 국내 지역 자료 재사용, 시도/시군구·지원일 반환 | 배포 시 자료 버전 관리 |
| `POST /api/name/v1/hanja-search` | 기존 사전/필드별 검토 자료의 서버 검색, 30행 cursor 페이지 | 추가 독음·뜻의 자료 검토 |
| `POST /api/name/v1/analyses` | 실제 원국 계산·확인된 뜻·서명 영수증, 지원 구조의 목 극대화 후보 | 다른 오행 역할·추가 구조 규칙 |
| `POST /api/name/v1/stories` | 영수증/cookie/입력·공개 후보 검증→토큰 검사→Supabase 예약→DeepSeek→정산. 실제 이송림 후보의 생성·보관·복원 확인 | 일부 JSON 실패의 생성 안정성 개선·대표 문체 검증 확대 |

서버 교체 지점은 `app/api/name/v1/[operation]/route.ts`, 프런트 응답 매핑은 `lib/client/api.ts`와 `lib/contracts.ts`입니다. 중첩 응답의 `Candidate`, `currentName`, `reasonCodes`는 화면용 어댑터 스키마입니다. 확정 API 계약이 미정으로 남긴 세부 구조는 백엔드 구현과 함께 매핑해야 합니다. 임의로 계산 패키지를 연결해 검증되지 않은 추천을 만들지 않았습니다.

브라우저에는 마지막 완료 묶음만 보관합니다. 기본 키 `name-web:last-result:v1`, 개발 키에는 `:development`가 붙습니다. 성공한 회상문과 선택 한자의 표시 자료도 묶음 안에 보관합니다. Web Locks/CAS, 탭 내 저장 직렬화, 세대 번호와 분석/후보 ID로 늦은 응답의 덮어쓰기를 막습니다. 잠금을 사용할 수 없으면 메모리에서만 보여주며 저장 실패를 안내합니다. 손상 기록은 자동 삭제하지 않습니다.

## 요청 제한

운영 원장의 점검·불확실한 청구 대조·보존 기간 정리는 [원장 운영 안내](../../docs/operations/name-ai-ledger.md)를 따릅니다. 실제 유료 기록을 초기화하지 않으며, 정리 SQL 검증은 세션 전용 임시 테이블에서 실행합니다.

서명된 브라우저 쿠키별로 분석 10회/분, 검색 60회/분, 신규 회상문 6회/분을 제한합니다. 같은 분석·후보·attempt는 회상문 한 건으로 셉니다. 첫 요청도 새로 발급한 서명 쿠키의 버킷을 사용해 다른 신규 방문자와 제한을 공유하지 않습니다. 서명 비밀키가 없는 개발용 한자 검색만 익명 버킷을 사용합니다. 메모리는 10,000개 창으로 제한하며 재시작·다중 인스턴스·쿠키 재발급으로 우회될 수 있습니다. 원자 비용 제한은 PostgreSQL이 담당합니다. 현재 로컬 서버에는 신뢰할 배포 프록시가 없어 전달 IP 헤더를 신뢰하지 않으며, 배포 시 호스팅의 검증된 IP 전달 경계를 별도로 설정·검증해야 합니다.

## 휠 입력

날짜(연·월·일), 지역(시·도·시군구), 한자에 공통 중앙 선택 휠을 사용합니다. 스크롤/클릭, 방향키·Home/End·PageUp/PageDown, Enter/Space를 지원합니다. 선택 완료로 반영하고 취소/Esc는 기존 값을 보존합니다. 기존 날짜 검증, 지역 API와 한자 검색/추가 페이지를 재사용합니다.

## 검증과 디자인 출처

[검증 보고서](../../docs/verification/2026-10-01-name-web.md)에 기능 검사, 화면 비교, 미검증 범위를 분리했습니다.

[Figma 원본](https://www.figma.com/design/mUsrQkJO2nnNEDLUbwKM3R)에서 아이콘 `back.svg`, `close.svg`를 제공된 에셋 URL로 가져왔습니다. Noto Sans KR은 가져오지 않았습니다. 기기 프레임 외곽선과 화면 높이에 따른 잘림은 제품 UI에 복제하지 않았습니다. PRD의 고정 공유 문구·DeepSeek 전송 안내를 시안의 요약 문구보다 우선했습니다.

Next.js가 생성한 `AGENTS.md`와 `CLAUDE.md`는 설치 버전의 로컬 문서 안내입니다. 직접 작성한 제품 정책이 아닙니다.

현재 설치는 Next 16.3.7입니다. [공식 보안 공지](https://nextjs.org/blog/upcoming-nextjs-security-release-september-2026)의 예정 패치가 아직 npm latest에 없음을 확인했습니다. 공개 배포 전 패치 적용과 재검증이 필요합니다. 이 작업에서는 로컬 서버만 실행했습니다.





시간 미상도 가능한 완전 원국을 내부에서 열거해 각 원국의 검토 규칙을 적용합니다. 모든 목표가 일치하고 모든 후보가 지원되는 경우에만 허용 오행 교집합으로 추천합니다. 원본 시주는 미확정으로 유지하며, 현재 제한된 지원 조건군에서 합의되지 않는 경우에는 보류합니다. 절입·일계·균시차 오차와 역사적 시간대 경계는 엔진 회귀 검사로 확인하며, 공급자의 공학적 오차 예산이 역사적 정확도 인증을 뜻하지는 않습니다.
