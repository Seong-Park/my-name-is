# 나의 이름은 — 제품 요구사항(PRD)

작성: 2026-09-30. **제품 요구사항 정본. 기획·계약은 확정됐으며, 실제 추천에 필요한 명리 규칙·자료 검증과 앱 구현·배포는 미완료다.**

이 문서는 제품 목적·경험·범위·출시 기준을 정의한다. 화면 세부 정책, 계산 조건표, DTO와 운영 동작은 아래 상세 문서를 단일 근거로 삼는다. 기획 확정과 실제 구현·검증 완료를 구분한다.

## 1. 제품이 답하는 질문

**“내 이름이 이랬다면 어땠을까?”**

출생정보와 현재 이름을 바탕으로 지금 이름을 살펴보고, 균형을 보완하는 이름과 강점을 더 강조하는 이름을 만난다. 각 이름에는 뜻과 추천 근거, 그 이름으로 살아왔을 법한 따뜻한 가상 회상문이 따른다.

명리·성명학의 전통 해석을 자기 탐색에 활용한다. 실제 과거를 알아맞히거나 이름이 삶을 바꾼다고 증명하는 서비스가 아니다. 현재 이름을 나쁘다고 단정하거나 개명을 권하지 않는다. 현재 이름이 잘 맞으면 그대로 인정하며 다른 이름을 반드시 더 나은 선택으로 표현하지 않는다.

MyLife 개인 중앙광장과 **독립된 익명 모바일 웹**이다. 광장·NPC·기존 계정 및 개인 기록 저장 흐름을 연결하지 않는다. 영유아부터 성인까지 연령 제한 없이 승인된 입력 범위에서 이용한다.

## 2. 핵심 사용자 흐름

1. 시작 화면에서 제품 질문을 읽고 ‘내 이름 살펴보기’를 누른다. 호환되는 브라우저 기록이 있으면 지난 이야기를 이어 볼 수 있다.
2. 출생 날짜·역법·시간·국내 지역을 입력한다.
3. 성씨와 이름을 각각 한글로 입력한다. 음절별 한자는 선택하며, 이름 분위기는 남성적·여성적·중성적·상관없음 중 고른다. 기본값은 상관없음이다.
4. 입력을 확인한 뒤 현재 이름의 평가 또는 확인 가능한 부분 풀이를 읽는다.
5. ‘좋은 이름 확인하기’로 균형형 이름의 한글·한자·뜻·추천 근거를 먼저 본다. 해당 후보의 회상문은 처음 열 때 생성한다.
6. ‘나의 장점을 극대화하는 이름’으로 목적이 다른 극대화형을 본다. ‘다른 이름 보기’는 이미 선정된 공개 후보 사이의 이동이다.
7. ‘친구한테 보내기’로 서비스 시작 URL을 전달한다. 친구는 자신의 정보를 입력한다.

분석 결과와 이름은 AI 회상문을 기다리지 않고 표시·보관한다. AI 장애가 이미 계산된 이름을 지우거나 추천 순위를 바꾸지 않는다.

## 3. 입력과 한자 선택

| 항목 | 제품 요구사항 |
| --- | --- |
| 출생일 | 양력 또는 음력·윤달. 양력 환산일 기준 1900-01-01~한국시간 오늘. 실제 날짜·윤달과 환산을 검증한다 |
| 현재 엔진 경계 | 검증된 공급자 상한은 2026-12-31. 이후 운영은 범위 확장과 경계 검증이 선행돼야 한다 |
| 출생시간 | 정확한 시·분 또는 모름. 대략 시각은 받지 않는다. 모름을 정오로 채우지 않는다 |
| 출생지역 | 채택된 국내 시·도·시군구 목록에서 명시적으로 선택. 상세 주소·해외 지역은 받지 않는다 |
| 한글 | 성씨 1~2음절, 이름 부분 1~5음절. 두 입력 칸을 분리하고 성씨 경계를 자동 추정하지 않는다 |
| 한자 | 음절마다 선택하거나 비워 둔다. 순한글 이름·한자를 모르는 이름·일부만 아는 이름도 진행 가능 |
| 분위기 | 두 추천 유형에 공통 적용하는 이름의 인상. 실제 성별을 추론하지 않는다 |

대운·세운을 제공하지 않으므로 계산용 성별을 수집하지 않는다. 날짜·지역·문자 정규화의 상세 경계는 [화면·입력 명세 §9](specs/2026-09-29-my-name-is-mvp-design.md)를 따른다.

한자 선택기는 **휠 형태와 검색 가능한 접근성 선택기**를 제공한다. 해당 음절의 독음·자형·확인된 뜻을 보여 주고, 키보드·스크린리더로도 선택할 수 있어야 한다. 미확인 한자를 추정하거나 미검토 뜻·오행을 생성하지 않는다. 한글을 수정하면 해당 성씨/이름 필드의 한자 선택을 비운다. 추천용 검토 목록 밖의 현재 이름도 검색 대상이며, 확인할 자료가 없으면 한글만으로 계속한다.

## 4. 현재 이름 평가

등급은 **이름 부분의 자원오행이 사주 균형과 어울리는지**에 대한 세 단계다. 성씨는 별도로 풀이하고, 발음오행과 수리 길흉을 종합 점수에 합산하지 않는다.

| 결과 | 성립 방향 |
| --- | --- |
| 잘 맞는 이름 | 필요한 평가 전제를 충족하고, 모든 이름 글자가 허용 오행이며 목표 오행을 포함 |
| 일부 보완할 이름 | 전제를 충족하고 비권장은 없지만 목표가 없거나 확인된 중립이 섞임 |
| 보완이 필요한 이름 | 전제를 충족하고 명시적으로 비권장인 이름 글자가 있음 |
| 부분 풀이·보류 | 한자 누락, 자료 미확인, 강약·목표 미확정 등으로 등급 전제 미충족 |

성씨 또는 이름의 한자가 하나라도 빠지면 전체 세 단계 등급을 붙이지 않는다. 확인된 한자의 뜻·오행과 한글의 초성 기준 발음 풀이는 제공하며, 한자 미입력을 감점하지 않는다. 새 이름 추천의 가능 여부는 별도로 판단한다.

‘허용 아님’을 ‘비권장’, ‘모름’을 ‘중립’으로 바꾸지 않는다. 정확한 전제·우선순위·역할 합의는 [핵심 규칙 §3](specs/2026-09-29-my-name-is-core-rules-proposal.md)가 정의한다.

## 5. 두 추천 유형과 후보 순서

| 유형 | 목표 | 두 글자 구성 |
| --- | --- | --- |
| 균형형 | 검증된 구조 분석과 억부·조후·통관·병약의 적용 판단이 합의한 보완 방향 | 한 글자 이상이 최종 목표 오행, 나머지도 명시적으로 허용된 오행. 목표·목표도 가능 |
| 극대화형 | 구조상 가장 강하다고 확인된 오행을 의도적으로 강조 | 두 글자 모두 선택된 최강 오행 |

기존 성씨를 유지하며 새 이름 부분은 항상 한자 두 글자다. 팔자 글자의 오행 개수나 일간 강약을 다섯 오행의 최강 판정으로 대체하지 않는다. 극대화형은 균형형보다 좋은 이름이라는 순위가 아니며, 이미 강한 기운을 강화할 때의 부담도 이야기한다.

균형형은 네 방법 각각의 적용 또는 비적용을 확인해야 한다. 필요한 방법이 미지원이면 합의로 세지 않는다. 공동 최강이 실제 확인된 때만 화→수→목→토→금의 서비스 동률 순서를 적용한다. 비교 불가에는 적용하지 않는다.

검토된 자원오행·뜻·독음과 유형별 조건을 통과한 뒤 **자연스러움 → 분위기 일치 → 전체 이름의 이웃 음절 간 발음오행 상극 수가 적은 순 → 고정 문자열 순**으로 정렬한다. 미검토 이름도 허용하되 검토된 자연스러운 이름 다음에 둔다. AI는 한자·목표·후보·순위를 결정하지 않는다.

현재 이름과 한글이 같은 후보를 제외하고, 유형 안에서도 한글 중복을 제거한다. 균형형 최대 3개를 먼저 정한 뒤 극대화형에서 그 한글을 제외한다. 각 유형 최대 3개이며 부족하면 실제 확보한 수만 보여 준다. 서버의 공개 개수 설정은 1~3개, 기본 3개이며 설정 파일 변경 후 재배포로 반영한다. 비공개 후보를 브라우저에 보내지 않는다. 같은 입력·규칙·자료 버전에서 추천과 순위는 동일하다.

발음오행은 표기된 초성만 사용하고 성씨부터 이름 끝까지 이웃 음절을 비교한다. 상극만으로 후보를 탈락시키지 않는다. 원획·81수리는 필요한 자료가 확인된 성씨 1~2글자·이름 1~2글자에 한해 참고 풀이로 제공한다. 이름 3~5글자나 수리 미지원은 다른 풀이·추천의 감점 사유가 아니다. 상세 표·산식·문자열 처리는 [핵심 규칙](specs/2026-09-29-my-name-is-core-rules-proposal.md)을 따른다.

## 6. 보류와 실패 경험

보류는 ‘이유 → 확인한 내용 → 가능한 다음 행동’ 순서로 설명한다. 이름이 나쁘다는 의미로 표현하지 않는다. 정상 해석 보류, 후보 자료 부족, 입력 오류, 처리 실패를 구분한다.

- 시간 모름 때문에 방향이 갈리면 정확한 시간을 아는 경우에만 ‘출생시간 추가하기’를 안내한다. 가능한 완전 원국 모두에서 목표와 허용 조합이 합의해야 하며, 시간 입력이 성공을 보장한다고 약속하지 않는다.
- 정확한 정보에서도 균형형이 보류되고 극대화형은 가능하면 ‘나의 강점을 담은 이름 보기’를 제시한다. 입력 변경을 해결책처럼 유도하지 않는다.
- 둘 다 보류면 ‘지금 이름 살펴보기’를 중심으로 확인된 소리·뜻만 제공한다. 추천 이름에 의존하는 회상문은 생성하지 않는다. 입력 확인과 서비스 공유는 가능하다.
- 통신·계산 실패는 이전 완료 기록을 유지하고 재시도를 안내한다. 회상문 실패는 이름 결과를 유지하며 서버 계약상 허용된 사용자 재시도 1회만 제공한다.

## 7. 따뜻한 가상 회상문

오래 간직한 편지나 책을 읽는 듯한 존댓말을 쓴다. ‘아쉬웠을 법한 순간 → 이름의 특성이 반영된 다른 선택 → 달라졌을지도 모를 과거의 여운’으로 구성한다. 실제 경험을 알고 있는 듯 단정하거나 이름의 효능을 약속하지 않는다.

후보 하나당 3문단, 문단별 40~100자·합계 120~300자다. 구조·길이를 검증하고 근거에 없는 명리 판정·한자 뜻을 만들지 않는다. 극대화형에는 특성과 부담을 함께 담는다. 성공한 문장은 보관해 다시 보여 주며 재생성 버튼을 두지 않는다.

서버가 계산한 연령대 0~5·6~12·13~18·19세 이상에 맞춰 장면을 조절한다. 영유아의 긴 후회, 아동의 직장·결혼, 성인의 특정 생애 경험을 전제하지 않는다. AI에는 검증된 추천 이름·뜻·분석 요약·연령대만 보내고 원본 출생일시·지역·현재 이름 원문·브라우저 식별자는 보내지 않는다. 생성 전에 외부 전송 내용을 안내한다.

## 8. 모바일과 접근성

따뜻한 미색 배경·먹색 글씨·큰 추천 이름·넉넉한 여백을 사용한다. 입력 식별과 버튼 조작을 장식보다 우선한다. 초기에는 시스템 글꼴과 CSS로 구성하며 외부 폰트·사진·질감 이미지를 추가하지 않는다.

320px 세로 화면에서 가로 스크롤 없이 읽고 조작할 수 있어야 한다. 주요 터치 영역은 최소 44×44 CSS px, 본문은 16px 이상이다. 가상 키보드·안전 영역·긴 문구·포커스·오류 레이블·상태 알림·동작 줄이기를 지원한다. 한자 dialog는 닫기·Esc·초점 복귀를 제공한다. PC는 동일 기능을 유지하고 최대 720px 읽기 폭을 기본으로 배치를 확장한다. 색상 토큰과 화면별 배치는 [화면 명세 §9](specs/2026-09-29-my-name-is-mvp-design.md)에 둔다.

## 9. 개인 기록과 공유

자체 서버에는 개인 입력·결과·프롬프트·회상문을 DB·로그·캐시·백업으로 보관하지 않는다. 요청 처리에는 서버 메모리를 사용하며, 브라우저에는 **한 사람의 마지막 완료 입력·결과·성공 회상문 한 묶음**을 저장한다. ‘어디에도 저장하지 않음’으로 안내하지 않는다.

저장 차단·용량 초과 등에는 현재 화면 결과를 유지하고 저장 실패를 알린다. 새 분석·삭제·다른 탭 변경 뒤의 늦은 응답이 과거 결과를 덮지 않아야 한다. 손상·알 수 없는 버전은 임의 복구·자동 삭제하지 않는다. 사용자가 ‘전체 삭제’로 이 브라우저 기록을 지울 수 있지만 서버 운영 원장·외부 제공자 보관까지 즉시 지우는 기능은 아니다. 기기 변경·브라우저 삭제 후 복구와 동기화는 제공하지 않는다.

카카오톡 공유는 사용자의 ‘친구한테 보내기’ 클릭으로 **서비스 시작 URL과 공통 소개문만** 전달한다. 개인 이름·출생정보·평가·결과 ID를 URL·본문·OG·이미지에 넣지 않는다. 카카오 로그인·친구 목록은 수집하지 않는다. SDK 실패 시 URL 복사, 복사 실패 시 선택 가능한 URL을 제공하고 취소를 전송 성공으로 표시하지 않는다.

## 10. AI 운영 목표와 범위 밖

별도 `apps/name-web`을 React·Next.js·TypeScript 앱과 Node Route Handler로 구성한다. 비상업 실험 배포는 Vercel Hobby를 대상으로 조건을 재확인하며, Neon PostgreSQL에는 운영 원장만 두고 개인 기록은 브라우저 localStorage에 보관한다. 아키텍처와 버전·배포 조건의 상세 책임은 ADR에 둔다.

AI 비용은 월 10만 원을 목표로 관리한다. 초기 서버 제한은 한국시간 기준 **월 $55·일 $3·동시 호출 4개**이며, 외부 요청 전에 확정액과 예약액을 원자적으로 검사한다. 환율·세금·수수료와 별도 호스팅 비용 때문에 원화 10만 원의 확정 청구 상한은 아니다.

2026-09-29 계약은 DeepSeek `deepseek-flash`를 선택했다. 이는 당시 설계 선택이며 현재 제공 상태·요금이 재확인됐다는 뜻이 아니다. 배포 전에 공식 모델·요금·토큰 계수·외부 보관 정책을 확인한다. 예산·운영 DB·요금 설정을 확인할 수 없으면 신규 AI 호출을 중단하고 이름 분석과 기존 기록 읽기는 유지한다. 비용·중복·상태만 운영 원장에 남기며 자동 AI 재시도를 하지 않는다. 정규 계약은 [API 및 운영 계약](specs/2026-09-29-my-name-is-api-contract.md)에 있다.

MVP에서는 계정·로그인·기기 동기화·서버 개인 기록·여러 사람의 기록 목록, 광장/NPC 연동, 해외 출생지역, 대략 시각, 대운·세운, 추천 순한글 이름, 개인 결과 공유, 성공 회상문 재생성, 관리자 화면을 제공하지 않는다. 이번 문서 정리는 앱 구현이나 배포를 포함하지 않는다.

## 독립 프로젝트 상태

이 PRD는 현재 `my-name-is` 독립 프로젝트의 요구사항이다. MyLife 중앙광장 및 기존 앱과의 비교·경계 설명은 설계 당시 기록으로 보존한다. 이 분리 작업은 제품 앱·배포를 구현하지 않았다. 사전과 수리 자료는 MyLife에서 가져온 제한된 스냅샷이며, 사전 전체의 검증 완료를 의미하지 않는다. 데이터베이스는 이 문서에 열거된 정적 JSON만 복사했고 라이브 DB·계정·개인 출생정보는 포함하지 않았다.
