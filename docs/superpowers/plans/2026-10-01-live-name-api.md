# 실제 이름 추천·DeepSeek 회상문 구현

목표: PRD대로 프런트·백엔드·API를 연결하고 최대 3개의 가상 출생 입력으로 실제 추천과 실제 DeepSeek 회상문을 확인한다. 개발용 고정 결과를 성공 증거로 쓰지 않는다.

기준: docs/PRD.md, 확정 core-rules/API 계약/화면 명세. 기존 Figma 프런트와 계산 패키지 재사용. 기존 브랜치·파일·키 보존, 배포/병합 없음.

## 순서와 완료 증거

- [ ] 서버 요청 경계: Origin, JSON, 추가 필드, 실제 읽은 16KiB 제한. 한자 검색은 기존 사전과 필드별 검토 자료를 서버에서 병합하고 미검토 뜻/오행을 노출하지 않는다. cursor의 버전·독음·범위 검증. 계약 테스트와 실제 HTTP 확인.
- [ ] 계산 연결: NatalBirthInput→원국, 확정 조건표 기반 관측/적용/보류, 현재 이름 평가, 추천 후보 필터/정렬/공개 개수. 연구 가설을 검증된 규칙으로 승격하지 않는다. 지원 조건표의 실제 근거/양성·음성 사례를 확보하고 테스트한다.
- [ ] 분석 영수증: cookie, purpose 분리 HMAC, 24시간 만료, 현재 버전/입력/공개 후보 재검산. 변조/만료/숨긴 후보 거절 테스트.
- [ ] 원장: PostgreSQL 두 운영 테이블, 원자 예약/정산/복구, 중복/재시도/일월/동시 한도 및 uncertain. 개인 입력·출력 비저장. DB 가능 여부는 비밀값을 출력하지 않고 확인한다.
- [ ] DeepSeek: 공식 모델·요금·tokenizer 확인, 입력 토큰 상한과 응답 검증, 자동 재시도 없음. 서버 키만 사용. 실제 호출 최대 3개 가상 입력에 연결해 결과 확인.

2026-10-01 후속: 실행 종료와 비용 불확실성을 분리하는 원장 전이를 보강했다. 종료 확인만으로 슬롯을 풀되 상한 계상과 재시도 거절을 유지하며 중복 확인은 무효다. 예약 날짜는 단일 statement 시각을 사용한다. 로컬 27개 검사·타입 검사·빌드 통과. 새 전이의 실제 DB 검사는 유료 기록 보존을 위해 재실행하지 않았다. 제품 stories 연결은 아직 완료하지 않았다.
- [ ] 프런트 통합: 실제 한자/분석/회상문, 보관/오류/재시도. 3개 이하 사례의 API·브라우저 증거, 비용·한계 기록. 테스트/타입/빌드 통과 후에만 전체 목표 완료 판단.

## 2026-10-01 현재 재확인

이전 턴은 프런트 구현과 검증 증거를 남긴 진전이다. 현재 서버는 config만 구현되어 있고 나머지 3개 POST는 503이다. DeepSeek 키 파일은 보존한다. 원국 이후 판정은 문서에서 아직 검증 미완료로 표시하므로 임의 오행 점수/고정 날짜 lookup으로 성공을 만들지 않는다. 이 제약은 전체 목표를 축소하는 사유가 아니라 실제 규칙 검증 단계의 남은 작업이다.

### 첫 구현 진행

- `lib/server/http.ts`: JSON object/Content-Type/실제 스트림 16KiB 한도 및 안전한 오류 반환. Origin 검사는 기존 route에서 유지.
- `lib/server/hanja.ts`: 기존 사전의 한 음절 독음 행과 필드별 검토 자료를 병합. 현재 이름용 미검토 행도 선택할 수 있지만 뜻은 null, 상태를 명시. 검토한 뜻만 노출. 안정 ID, 30행 페이지, 사전 버전·독음·offset cursor 검사. Node crypto를 사용하는 서버 경로에만 연결.
- 테스트 9개, 타입 검사, 프로덕션 빌드 통과. 실제 3100 서버의 한자 검색 HTTP 200 확인. 전체 목표 완료 증거가 아니며 analyses/stories는 아직 미연결.
- 비밀값을 노출하지 않고 DeepSeek 키 있음, DATABASE_URL 없음 확인. `.env.local`에 기존 키를 보존하며 빈 DB 항목만 추가. 사용자에게 개발 Neon DB 준비 여부를 비동기 질문함. DB 없이 비용 원장을 우회해 유료 호출하지 않는다.
- 다음 작업: 입력/한자 ID/지역 서버 검증 → 기존 NatalBirthInput/원국 계산 연결. 명리 지원 조건의 검증 미완료는 별도 해결해야 하며 단순 점수화로 대체하지 않는다.

### 서버 입력 검증 및 DB 준비

- 사용자가 개발 DB 생성이 필요하다고 답함. 사용 가능한 Neon 커넥터는 없고, Neon 콘솔은 로그인 화면이므로 사용자 로그인 완료를 요청함. DB는 아직 생성하지 않았음.
- `lib/server/input.ts`: 공통 입력 검증 재사용, 성명 trim/NFC와 기본 분위기 any, 서버 지역 목록 및 한자 행 ID/독음 대조. NatalBirthInput 매핑은 서버 좌표·시간대만 사용하고 분위기를 성별로 변환하지 않음. analyses 라우트에 입력 검사 연결.
- 공통 검증의 상속된 키 허용 및 분위기 문자열 강제 변환을 제거. 기존 기록의 역법/분위기 검사도 문자열 배열을 허용하지 않도록 수정.
- 실패 테스트 확인 후 구현. 테스트 10개, 타입 검사, 프로덕션 빌드 통과. `.env.local`의 gitignore 적용 재확인. 이번 단계는 서버 검증이며 추가 시각 검증이나 실제 AI 생성 성공을 의미하지 않음.
- 남은 작업: 원국 계산과 검증된 추천 판정 연결, 영수증, PostgreSQL 원장, 실제 DeepSeek 호출 및 최대 3개 가상 입력의 종단 검증.

### 원국 어댑터·영수증 모듈

- `lib/server/calculation.ts`는 기존 실제 역법 엔진을 호출하고 시간 미상/경계 불확실성과 버전을 보존한다. 생일을 지난 만 나이로 회상문 연령대를 구분한다. 원국 판정/추천을 추가한 것은 아니다.
- `lib/server/receipt.ts`는 목적별 HMAC 키, 24시간 영수증, 입력/브라우저/버전 결합, 불투명 후보 ID, 서명된 생성 시각으로 30일 절대 만료를 검사하는 HttpOnly cookie를 구현했다. `.env.example`에 서버 전용 서명 키 항목을 추가했다. 라우트에는 아직 연결하지 않았고 사용자 키 파일은 수정하지 않았다.
- 테스트 12개, 타입 검사, 프로덕션 빌드 통과. 실제 DeepSeek 호출 및 이름 추천 성공 검증은 여전히 미완료다.
- 사용자 답변: 개발 DB는 Supabase로 진행. PostgreSQL 운영 계약은 유지하며 공급자별 연결/보존 설정만 대체한다. Neon 생성은 진행하지 않는다.
- Supabase 콘솔도 로그인 화면인 것을 확인했다. 사용자는 직접 프로젝트 생성 후 `DATABASE_URL`을 입력하기로 선택했다. 연결 문자열 값은 읽어 출력하지 않고 준비 여부만 확인한다. 아직 DB 생성/연결 검증 완료로 간주하지 않는다.

### 비용 원장 구현 및 연결 검사

- 사용자가 Supabase `DATABASE_URL` 입력을 알림. 공식 Studio 소스의 CA 배포 경로를 확인하고 공개 인증서를 내려받아 서버 인증서/호스트명 검증을 유지한 연결을 구성했다. TLS 검증은 통과했지만 DB가 `28P01` 인증 실패를 반환함. 비밀번호 앞뒤 예시 괄호 여부를 값 출력 없이 확인하고 사용자에게 제거 방법을 안내했다. 아직 마이그레이션을 실행하지 않았음.
- `db/001-cost-ledger.sql`, `lib/server/ledger.ts`: 두 테이블, bigint 예약/정산, unique 키/attempt, transaction advisory lock, 일·월·동시 한도, reserved 복구, dispatching→uncertain, 중복 정산 방지, 실제 비용 초과 시 중단 표시 구현. 보존 기간 정리·운영자 정산과 라우트 연결은 남음.
- `scripts/database.ts`: 설정 값 노출 없는 연결 검사/신규 스키마 적용. `scripts/test-ledger.ts`: 빈 개발 원장에서만 실행하는 실제 DB 동시성/중복/정산/재시도 검사. 아직 인증 실패라 실제 DB 검증 미실행. 로컬 13개 테스트·타입 검사·빌드 통과는 이를 대신하지 않음.

### Supabase 연결 및 실제 원장 검증 진전

- 사용자가 비밀번호 예시 괄호를 제거한 뒤 PostgreSQL 17 연결 성공. `name_private`가 없음을 확인하고 001 마이그레이션 적용 완료. 클라이언트→pooler는 CA/호스트 검증을 사용한다. `pg_stat_ssl`이 보고하는 pooler→backend 연결은 false이며 이를 클라이언트 TLS 상태로 오인하지 않도록 진단 필드명을 구분했다.
- 실제 DB에서 날짜 SQL 별칭 구문 오류를 발견해 수정. 동시 검사 중 연결 풀 획득 대기 부족을 확인해 15초로 조정. active client의 query 사이 연결 종료 error 이벤트가 프로세스를 종료하지 않도록 공통 pool 생성 경로에 처리기를 추가했다.
- 실제 DB의 동시 6개 중 4개 예약, 같은/다른 키의 동일 attempt, 키 재사용 충돌, dispatch 1회, 중복 정산 거절, uncertain 비용의 1회 이동, 확정 실패 후 1회 retry 검사 통과. 검증 데이터는 개인 입력이 없는 전용 가상 운영 ID이며 DeepSeek는 호출하지 않았다.
- 일/월 예산·예약 만료·lost dispatch 슬롯 유지·초과 정산 후 중단 검사를 추가해 실행 중. 해당 결과는 아직 완료 증거에 포함하지 않는다.
- 후속 결과: 추가한 일/월 예산·예약 전 거절의 attempt 비소모·예약 만료·lost dispatch 슬롯 유지·초과 정산 후 중단 모두 실제 Supabase에서 통과(스크립트 종료 코드 0). 생년월일 입력/이름 추천/실제 LLM 검증과는 별도인 운영 원장 검사다. 날짜·월말 경계, 보존/대조 runbook, 실제 공급자 정산 및 전체 라우트 연결은 남아 있다.

### DeepSeek 최초 실호출 검증

- 공식 V4 tokenizer JSON을 Git 제외 캐시에 확보하고 Tokenizers.js로 공식 system/user template 계수를 구현. 서버 fetch(30초/1회), usage 대조, 정확한 3문단/길이/완료/추가 키 검증 구현. 테스트 15개와 빌드 통과.
- 개발용 문장 자료 한 개로 최초+attempt 1을 Supabase 예약/dispatch/정산 경로를 거쳐 실제 DeepSeek 호출. 최초 STORY_INVALID, 재시도 58·57·58자 통과. 로컬 395→실제 419 토큰 두 번, 비용 합계 $0.000235068, 원장 2건/성공1/실패1/예약0 확인. 실제 호출 원장은 삭제하지 않음.
- 상세 근거: `docs/verification/2026-10-01-deepseek-calibration.md`. 실제 출생정보→이름 추천→회상문 종단 성공이 아니므로 목표 완료로 처리하지 않는다. 제품 라우트는 계속 AI_DISABLED다.


### 실제 분석 라우트와 사용자 추가 요청

- 원국 계산/검토된 뜻/서명 영수증을 분석 라우트에 연결, 유효 입력 200 부분 풀이를 실제 브라우저에서 확인. 미검증 추천은 RULES_NOT_VERIFIED로 명시하며 후보를 만들지 않는다. 추천/회상문 종단 목표는 미완료.
- 사용자 요청에 따라 날짜·지역·한자를 중앙 선택 휠로 통일했다. 기존 Dialog/API/검증을 재사용하고 취소·Esc·초점 복귀를 보존. 320/390/1440px 확인과 18개 테스트 결과는 검증 보고서에 기록했다.


### 독립 기준 자료 직접 조사 승인 및 진행

- 사용자: 별도 기준 자료가 없으며 직접 찾아 저장해도 된다고 승인. 추가 사실 선택을 사용자에게 요구하지 않고 원문 사례를 조사했다.
- 滴天髓闡微 독립 명식 3건을 강약/취용의 명시 근거와 미기재 필드로 나눠 기록. DC-02/03과 같은 원국을 내는 2012-02-23 12:00 및 1964-03-16 08:00 서울 역법 동형 입력을 기존 엔진으로 확인. 실제 인물 출생일이나 추천 성공 데이터가 아니다. 기존 1990-05-21 입력과 합쳐 최대 세 입력 범위 유지.
- 실제 분석의 발음오행 누락 수정, stories 중복 방지 키 경계 검사 추가. 20개 테스트·타입 검사·빌드 및 실제 브라우저 풀이 확인. 최종 강약·네 방법·최강·추천·회상문 종단 연결은 미완료이며 목표를 축소하지 않는다.


### 후보 선정 계약 구현

- 기존 검토 한자 21자형–독음 쌍으로 목표/보조 조합과 결정적 순위, 중복·현재 이름·노출 개수 처리 구현. 명리 목표 null에는 후보를 생성하지 않으며 아직 해석 모듈이 제공할 검증된 목표는 없다.
