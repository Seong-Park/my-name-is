# 나의 이름은 — 확정된 도메인 계약 및 명리·데이터 출시 조건

작성일: 2026-09-29.

상태: **제품·도메인 계약 확정. Q1·Q2·Q3은 사용자 승인, 예외와 수용 조건은 위임된 판단으로 확정했다. 명리 조건표·추천 한자 목록·코드의 구현 및 검증은 미완료다.** [MVP 기획](2026-09-29-my-name-is-mvp-design.md)의 다방법 합의 A와 구조적 판정 B를 유지한다. 이 문서는 제품 설계를 닫으며 실제 명리 원국 판정 규칙의 납품을 대신하지 않는다.

## 1. 확정 범위와 납품 상태

이름 부분의 자원오행 적합성으로 3단계를 평가하고, 성씨는 별도 풀이한다. 초기 추천 한자는 200자·오행별 40자 검토를 작업 목표로 삼으며 수리는 출처·산식이 확인된 범위만 제공한다. 발음오행 초성표, 자연스러움·분위기·상극 수·고정 문자열 순서, 두 유형의 구성과 중복 제외는 MVP 기획을 따른다.

| 항목 | 확정한 것 | 아직 납품되지 않은 것 |
| --- | --- | --- |
| 명리 판정 | 근거·합의·보류·지원 범위 수용 계약 | 신강·신약, 네 취용 방법, 최강 오행의 개별 조건표와 검증 |
| 현재 이름 | §3의 3단계 조건표와 부분 풀이 경계 | 실제 원국별 목표·허용·중립·비권장 판정 자료 |
| 추천 데이터 | 한자별 근거와 검토 기준, 200자 작업 목표 | 채택 정책을 만족한 초기 한자 및 이름 검토 목록 |
| 수리 | 1930년 원전 81행·네 산식, 합산 1~81 제공, 강희 전사 기준 26자 원획 | 사용자용 참고 문구·추가 글자 검토·계산 구현 |

기존 원국 계산 M2·M3의 구현 존재는 후속 구조·용신 판정 완료를 의미하지 않는다. 이번 작업은 문서 검토이며 엔진 테스트나 데이터 전수 검증을 실행한 기록이 아니다.

## 2. 명리 판정: 유지할 원칙과 실행 조건

### 2.1 관측과 최종 판정을 분리한다

[ADR-004](../references/mylife/docs/bazi/adr/ADR-004-strength-model.md)의 계절·통근·생조·극설모를 별도로 보존한다.

| 관측 | 구체적으로 보존할 내용 | 하지 않을 처리 |
| --- | --- | --- |
| 월령 | 절기로 계산한 월지와 채택 표의 계절 상태 | 양력 월이나 팔자 글자 수로 대체 |
| 통근 | 어느 지지의 어느 지장간인지, 본기·중기·여기, 위치와 천간과의 관계 | 본기 60·중기 30·여기 10 같은 미채택 가중치 대입 |
| 노출·생조 | 실제 천간, 비겁·인성의 위치와 연결 근거 | 도움을 주는 글자가 많다는 이유만으로 신강 확정 |
| 극·설·모 | 관살·식상·재성을 나누어 기록 | 세 작용을 하나의 동일한 감점으로 환산 |
| 합·충 등 관계 | 관계와 관련 위치, 실제 효과를 판정한 규칙 | 합이 있으면 자동 오행 변환, 충이 있으면 뿌리 삭제 |

지장간 membership과 역할은 [채택된 P1 표](../references/mylife/docs/bazi/RULE_SOURCES.md#p1)를 재사용한다. 월중 사령 일수나 토월 계절 처리까지 이미 확정된 것으로 보지 않는다.

《子平真詮》의 계절·뿌리·제약 사례는 계절만으로 강약을 정하면 안 된다는 근거가 된다. 이것이 현대적인 가중치나 다섯 오행 순위표를 제공하는 것은 아니다. [원문 전사 「論十干得時不旺失時不弱」](https://www.donglishuzhai.net/chapter/3719.html).

### 2.2 신강·신약 판정의 실행 계약

개별 판정 규칙에는 성립 조건, 반례·제외 조건, 결론, 출처 위치와 기준 사례를 함께 둔다. 현재 자료만으로 성립 조건의 모든 행을 작성했다고 주장하지 않는다.

| 상황 | 판정 처리 |
| --- | --- |
| 적용 조건과 제외 조건을 모두 확인한 규칙들이 같은 강약 방향을 지지 | 그 규칙의 지원 범위에서 확정 가능 |
| 서로 반대 강약 결론의 규칙이 함께 성립하고 해결 규칙이 없음 | 강약 미확정 |
| 필요한 합충 효과·특수 구조·계절 처리 규칙이 미지원 | 강약 미확정 |
| 적용할 규칙이 없음 | 강약 미확정. 중화·균형 좋음으로 바꾸지 않음 |
| 입력의 실제 가능한 원국마다 결론이 다름 | 강약 미확정 |

독립된 규칙이 많다는 이유로 다수결하지 않는다. 범위가 겹치는 규칙은 예외 관계를 명시해야 하며, 파일 순서상 첫 규칙으로 결정하지 않는다.

**남아 있는 실질 작업:** 월지별 계절 상태와 토월 처리, 뿌리 깊이·위치의 비교, 득시·득지·득세와 제약이 엇갈릴 때의 결론, 특수 구조의 적용·비적용 조건을 원문과 독립 기준 사례로 고정해야 한다. 이 작업은 사용자에게 사실 여부를 선택하게 할 문제가 아니다.

### 2.3 억부 검색 공간

[ADR-006](../references/mylife/docs/bazi/adr/ADR-006-yongshin-priority.md)의 생극 관계를 펼친 표다. **아래 오행 모두를 추천에 허용한다는 뜻은 아니다.** 개별 원국에서 기능·과다·뿌리·노출·다른 판단과의 충돌 검토를 통과해야 한다.

| 일간 오행 | 신약일 때 검토 | 신강일 때 검토 |
| --- | --- | --- |
| 목 | 수·목 | 화·토·금 |
| 화 | 목·화 | 토·금·수 |
| 토 | 화·토 | 금·수·목 |
| 금 | 토·금 | 수·목·화 |
| 수 | 금·수 | 목·화·토 |

강약이 미확정이면 균형형을 보류한다. 상대적인 오행 1위라는 사실만으로 그 오행의 일간을 신강으로 판정하지 않는다.

### 2.4 다방법 합의의 선택 계약

조후·억부·통관·병약 각각 다음을 먼저 결정한다.

- 적용: 검토한 조건표에 해당하며, 실제로 적합한 목표와 보조 오행을 반환한다.
- 비적용: 검토한 조건표로 해당 방법이 필요하지 않음을 확인했다. 비적용의 근거도 남긴다.
- 정보 부족·미지원·미평가: 합의에 참가한 것으로 처리하지 않는다. 필요한 판단이 끝나지 않았으므로 균형형을 보류한다.

최종 선택은 아래 순서로 처리한다. 이것은 검증된 방법별 결과를 받는 제품 계약이며, 원국별 선택 조건표는 별도로 납품해야 한다.

1. 네 방법의 적용 여부와 필요한 진단을 완료한다. 일반 규칙을 적용할 수 없는 특수 구조가 남으면 보류한다.
2. 적용 방법들이 각각 **최종 목표로 허용한다고 명시한** 오행 집합의 교집합을 구한다. 억부 검색 공간을 이 집합으로 그대로 사용하지 않는다.
3. 공통 목표가 없으면 충돌로 보류한다. 적용 방법이 하나도 없으면 목표를 만들지 않는다.
4. 공통 목표가 하나이고, 각 방법의 원국 적합성·예외·특정 천간 조건을 모두 충족하면 그 오행을 이름 추천의 목표로 선택한다. 방법 간 합의와 별도로 이 조건 통과 근거를 보존한다.
5. 공통 목표가 둘 이상이면 별도의 출처·근거 있는 선택 규칙이 있을 때만 하나를 고른다. 없으면 보류한다. 극대화형의 화→수→목→토→금 순서를 균형형에 전용하지 않는다.
6. 두 번째 한자로 허용할 오행 역시 각 방법에서 보조로 허용한 범위의 교집합을 사용한다. 최종 목표는 포함하되, 목표를 생하는 오행을 자동 추가하지 않는다. 보조 오행을 판정하지 못하면 목표 외 조합은 허용하지 않는다.

예: 억부의 실제 허용 목표가 목·화, 조후가 화이고 통관·병약은 비적용임이 확인됐다면 공통 목표는 화다. 그러나 조후가 미구현이면 억부만으로 화를 확정할 수 없다.

특정 천간을 요구하는 조건은 오행과 구분한다. 예를 들어 丁이 필요한 조건을 FIRE 자원오행 한자 하나가 실제로 충족한다고 표현하지 않는다. 이름은 그 오행의 상징을 담는 것이며 원국에 새 천간을 삽입하지 않는다. 천간별 차이를 오행 단위 추천으로 옮길 근거가 없는 규칙은 이름 추천용으로 미지원 처리한다.

### 2.5 극대화형의 비교·동률·보류 계약

- 확정하려는 오행과 나머지 네 오행 사이의 구조적 비교 근거가 필요하다. 나머지 네 오행끼리 전체 순위를 정할 필요는 없다.
- 비교마다 강함·약함·동률·비교 불가를 구분한다. 동률은 이를 판정하는 규칙이 성립한 경우에만 반환한다.
- 어떤 오행이 나머지 모두보다 강하면 단독 최강이다. 공동 최강은 집합 내부의 동률과 집합 외부에 대한 우세가 모두 확인돼야 한다.
- 최강 확정에 필요한 관계에서 비교 순환, 미확정 관계, 조건 누락이 있으면 해당 유형을 보류한다. 최강 후보보다 약한 나머지 오행들 사이의 순위 미확정만으로 보류하지 않는다.
- 공동 최강이 확인된 경우에만 이미 확정한 화→수→목→토→금 순서를 적용한다.

단순 관측 벡터의 모든 축에서 앞서는 방식을 도입해도, 축별 강약 기준과 생극 작용의 비선형성이 해결되지는 않는다. 같은 관측 벡터도 실제 명리적 동률을 뜻하지 않는다. 따라서 이를 구조상 최강 판정의 대체 규칙으로 채택하지 않는다.

**현재 미완성:** 위 계약에서 사용할 개별 구조 비교 조건표. 이를 작성·검토하기 전에는 극대화형 제공률을 추정하거나 대부분의 입력을 지원한다고 약속할 수 없다.

### 2.6 시간 미상 후보의 합의는 이름 조합까지 확인한다

실제 가능한 연동된 완전 원국 후보를 생성해야 한다. 기존 M3의 기둥별 후보를 임의 조합하거나 정오로 대신하지 않는다.

- 각 원국에서 해당 유형의 목표를 확정할 수 있어야 한다.
- 목표가 전부 같아도 보조 허용 오행이 다를 수 있다. 균형형의 두 번째 글자는 모든 원국에서 허용되는 교집합에 속해야 한다.
- 예: 모든 후보의 목표가 화라도 한 원국은 목·화, 다른 원국은 토·화를 허용한다면 화·화만 공통으로 사용할 수 있다.
- 현재 이름의 평가도 모든 실제 원국에서 같은 등급·호환되는 근거가 나와야 종합 등급을 제공한다. 다르면 부분 풀이로 남긴다.

### 2.7 명리 자료의 확인 수준

| 분야 | 권고 자료·방식 | 확인 수준과 한계 |
| --- | --- | --- |
| 기본 간지·지장간·생극 관계 | 이미 채택한 M2와 RULE_SOURCES | 기존 채택 범위 재사용. 원국 강도까지 검증한 표가 아님 |
| 신강·신약 관측과 반례 | 《子平真詮》의 계절·뿌리·제약 논의, ADR-004 | 관측 근거 있음. 자동 판정 전체 조건표는 별도 작업 |
| 조후 조건의 자료 기반 | 《窮通寶鑑》의 일간·월별 본문을 우선 검토하고 예외까지 분리 | 전사 원문 일부 직접 확인. 120개 일간×월지와 원국 예외 전수 정규화는 미완료 |
| 통관·병약 | 적용·비적용 조건과 대응이 명시된 원문 단위 규칙 | 기존 조사에서 완성 표를 확보하지 못함. 미지원 자동 통과 금지 |
| 최강 오행 비교 | 명시적 구조 비교 규칙과 반례 | 다섯 오행 공통 점수표를 원문에서 발견한 상태가 아님 |

《窮通寶鑑》 갑목 봄 부분에도 丙·癸의 조합, 과다한 금·수 및 국의 구성에 따라 다른 판단이 나온다. 첫 문장만 뽑은 일간×월지의 단일 오행표로 축약하지 않는다. 원문의 부귀·질병·성별에 관한 단정은 서비스 설명으로 복제하지 않는다. [원문 전사](https://zh.wikisource.org/zh-hant/穷通宝鉴).

**출시 계약:** 검증 가능한 지원 조건군부터 늘린다. 각 조건군에서 네 방법 모두 적용 또는 비적용을 실제로 결정할 수 있어야 한다. 미지원 범위는 보류한다. 현재는 네 방법 중 하나라도 전 영역 미지원이면 균형형 전체가 보류될 수 있으므로, UI 완성만으로 서비스가 출시 준비됐다고 볼 수 없다. 지원 조건군 확보 없이 ‘대표 몇 명만 성공하는 규칙’이나 임의 가중치를 출시용 판정으로 바꾸지 않는다.

## 3. 현재 이름 3단계 평가

### 3.1 평가 범위

**확정: 바꿀 수 있는 이름 부분의 자원오행 적합성으로 3단계를 정한다.** 성씨는 고정된 배경으로 별도 풀이하며, 전체 발음오행·수리 계산에는 포함한다. 성씨의 오행 하나 때문에 모든 추천 이름이 낮은 등급이 되는 일을 피하기 위한 제품 선택이다.

사용자에게 ‘성씨까지 포함한 명리 종합 점수’로 표시하지 않고 ‘사주 균형과 이름 한자의 어울림’이라는 평가 범위를 설명한다.

기존 합의대로 성씨 또는 이름의 한자가 하나라도 빠지면 전체 3단계 평가는 제공하지 않는다. 모든 한자를 입력했더라도 평가에 필요한 자원오행 자료나 균형 판정이 미확정이면 부분 풀이만 제공한다. 성씨 한자의 자형·독음은 확인해야 하지만 성씨의 자원오행이나 원획 자료만 미확인인 것은 이름 부분 등급의 보류 사유가 아니다. 그 성씨의 해당 풀이만 미제공한다. 발음오행·수리 길흉을 종합 점수로 합산하지 않는다.

### 3.2 이름에 쓰인 각 오행의 상태

균형 분석 결과에서 다음 범주를 구분한다. 사용하지 않은 오행을 자동으로 기신으로 지정하지 않는다.

| 구분 | 뜻 |
| --- | --- |
| 목표 | 현재 균형형 추천의 최종 목표 오행 |
| 허용 | 해당 사주에서 보완에 적합하다고 명시적으로 확인한 오행. 목표 포함 |
| 비권장 | 해당 사주의 균형 보완에 반한다고 명시적인 근거로 판정한 오행 |
| 중립 | 적용 규칙에서 보완 또는 비권장 어느 쪽도 아닌 것으로 확인한 오행 |
| 판단 불가 | 자료·분석이 부족하거나 충돌해 위 범주를 정하지 못한 오행 |

‘허용이 아님’은 ‘비권장’과 다르다. 아무 규칙도 없어서 모르겠다는 상태도 ‘중립’으로 바꾸지 않는다. 이 범주를 산출하는 규칙이 없으면 평가를 보류한다.

### 3.3 평가 조건표

평가 전제: 균형 목표가 확정되고, 입력한 모든 한자가 확인돼 있으며, 이름 부분에 쓰인 각 한자의 자원오행과 위 범주가 판명돼야 한다. 이 전제를 확인한 뒤 아래 순서로 평가한다.

| 순서 | 조건 | 표시 |
| --- | --- | --- |
| 1 | 전제 미충족 또는 이름에 쓰인 오행 중 판단 불가가 있음 | 등급 없이 부분 풀이 |
| 2 | 이름 부분에 명시적으로 비권장인 오행이 하나 이상 있음 | 보완이 필요한 이름 |
| 3 | 비권장이 없고, 모든 글자가 허용 오행이며, 목표 오행이 한 글자 이상 있음 | 잘 맞는 이름 |
| 4 | 나머지: 비권장은 없지만 목표가 없거나 확인된 중립 오행이 섞임 | 일부 보완할 이름 |

이름 부분이 1~5글자인 경우에 같은 조건을 적용한다. 비율·100점·글자별 가중치는 만들지 않는다. 목표가 두 번 있다는 이유로 한 번 있는 이름보다 무조건 좋게 평가하지 않는다. 상극 발음이나 수리 하나가 이 등급을 덮어쓰지 않는다.

트레이드오프: 비권장 글자 하나로 가장 낮은 단계가 되는 보수적인 규칙이다. 대신 그 글자와 이유를 반드시 설명한다. ‘나쁜 이름’이나 개명을 해야 한다는 판정으로 표현하지 않는다.

### 3.4 합의와 충돌의 처리

현재 이름에 쓰인 오행은 방법별 근거를 비교해 허용·비권장·중립·판단 불가 중 하나로 정한다. 목표는 허용의 부분집합이다. 적용 방법 중 허용과 비권장이 충돌하면 판단 불가다. 허용은 모든 적용 방법이 보완 가능하다고 확인한 범위이며, 비권장은 모든 적용 방법의 역할 평가가 완료되고 하나 이상의 명시적 악화 근거가 있으며 나머지가 비권장 또는 중립일 때만 사용한다. 모든 적용 방법이 중립으로 확인하면 중립이다. 나머지 혼합·미판정은 판단 불가이며 다수결하지 않는다. 비적용 방법은 근거를 남기고 오행 역할 합의에서 제외한다.

동일 오행의 역할이 원국 후보에 따라 달라도 §3.3의 등급과 설명 근거가 모두 호환되는 경우에만 종합 등급을 제공한다. 한 후보라도 등급이 없거나 등급이 다르면 부분 풀이로 남긴다. 시각 미상에 따른 원본의 불확실성은 동일 등급이 나와도 지우지 않는다.

예를 들어 목표=수, 허용=수·금, 비권장=화, 중립=목·토가 실제 분석으로 확인됐다면 이름 부분이 수·수는 잘 맞음, 목·수는 일부 보완, 화·수는 보완 필요다. 이는 조건표 설명용 가정이며 실제 인물이나 한자의 검증 결과가 아니다.

## 4. 한자·성명학 데이터 계약

### 4.1 전체 사전과 추천용 검토 목록을 구분한다

기존 사전은 10,381개 독음별 행과 9,494개 고유 한자를 갖지만, 글자별 출처·검토 정보가 없다. [기존 데이터 조사](../research/2026-09-29-my-name-is-mvp-research.md).

**확정: 초기 추천용 한자는 고유 한자 200자를 작업 목표로 삼고, 오행별 40자를 우선 검토한다.** 이는 검토량의 목표이며 서비스가 200자 검토 완료 전에는 절대 동작할 수 없다는 기술 조건은 아니다. 오행별 수량을 맞추려고 모호한 글자를 억지 분류하거나 검토 기준을 낮추지 않는다. 200자만으로 모든 성씨·분위기에 3개씩 확보된다고 보장하지 않는다.

현재 이름의 입력은 이 추천 목록으로 제한하지 않는다. 목록 밖 한자는 검색·입력하되 자료 상태에 따라 확인된 뜻만 보여주거나 해당 항목을 미확인으로 남긴다. 기존 사전의 모든 오행을 자동으로 신뢰하지 않는다. 자원오행을 확인하지 못한 현재 이름에는 3단계 평가를 만들지 않는다.

### 4.2 추천에 사용할 수 있는 행의 조건

| 항목 | 채택 조건 | 누락·충돌 시 |
| --- | --- | --- |
| 자형·독음 | 법원 공식 자료에서 해당 조합과 예외 조건을 확인하고 기준일·위치 기록 | 추천 제외. 임의 독음 추가 금지 |
| 뜻 | 출처가 확인된 사전의 해당 글자·뜻 확인, 서비스에 쓸 풀이를 직접 작성 | 뜻을 AI가 창작하거나 독음을 뜻으로 사용하지 않음 |
| 자원오행 | 채택한 해석 근거와 글자별 검토 기록에 따라 하나로 확정 | 추천 제외. 부수나 초성만으로 자동 대입하지 않음 |
| 사용 부적합 | 검토된 한자 제외 목록과 정확한 이름 제외 규칙 통과 | 추천 제외, 이유 기록 |
| 원획수 | 글자별 원획 자료·판본과 대조 | 수리만 미제공. 뜻·자원오행 등 다른 추천 필수 조건과 구분 |

법원 확인은 허용 자형·독음을 다루며 자원오행의 정답을 제공하는 절차가 아니다. 전수 자동 대조는 완전한 원본 확보 후 가능한 별도 작업으로 두고, 먼저 실제 추천 후보의 자형·독음을 확인한다. [법원 인명용 한자 조회](https://efamily.scourt.go.kr/cs/CsBltnWrtList.do?bltnbordId=0000010).

**검토 경계 정정(2026-09-30 후속):** 자연스러움·분위기의 미검토는 이름 조합의 후순위 조건이며 개별 한자의 추천 적격을 막는 조건이 아니다. 정확한 이름 제외 목록은 후보 조합 단계에 적용한다. 원획 미확인 역시 수리 참고 풀이만 막는다. 자료의 검토 상태를 저장하는 것과 새로운 필수 통과 조건을 만드는 것을 구분한다. 공식 자형을 수동으로 대조한 경우 그 방법·위치를 기록할 수 있으며 자동 추출에 실패했다는 사실만으로 모든 수동 확인을 무효화하지 않는다. 다만 호환 한자·이체자 등 실제 코드포인트 식별이 불명확한 행은 별도로 보류한다.

뜻의 출처 확인과 서비스용 짧은 뜻풀이의 직접 작성을 채택 기준으로 유지한다. 이번 26자에서 작성한 짧은 한국어 의미 요약을 검토했으며, 원본 사전 DB·폰트·이미지·장문 해설의 재배포 권리가 확인되지 않았다는 이유를 이 문구 전체의 자동 차단 조건으로 확대하지 않는다. 출처와 직접 작성 사실은 보존한다. 이는 원본 자료의 일괄 이용권 또는 법적 적법성을 보증하는 결정이 아니다. 실제 독음별 뜻이 미확정인 金·김, 오행 미분류와 명시적으로 제외한 글자는 계속 보류한다.

한자+독음을 별도 키로 관리한다. 金의 ‘김’과 ‘금’, 林의 ‘림’과 ‘임’ 등을 첫 독음 하나로 덮지 않는다. 자형·이체자의 원문 코드 포인트를 보존하며, Unicode 정규화나 모양 유사성만으로 법원 허용 자형이 같다고 판단하지 않는다. 한글 비교용 정규화와 공식 한자 자형 확인은 별도 처리다.

### 4.3 자원오행의 채택 방향

채택 기준은 **단일 검토 정책에 따른 글자별 명시적 분류**다. ‘공식 자원오행’이라는 명칭은 사용하지 않는다.

- 기존 JSON은 후보 조사 자료로 사용하며 그대로 검증 완료 처리하지 않는다.
- 분류 출처·뜻·자형을 함께 확인하고, 한 글자의 오행이 자료마다 갈리면 선택 근거를 기록하거나 초기 추천 목록에서 제외한다.
- 부수가 같다고 모두 같은 오행으로 추정하지 않는다. 발음오행으로 빈 자원오행을 채우지 않는다.
- 출처 문헌의 분류를 채택한 값과 서비스가 자체 해석한 값을 구분한다. 초기 추천에는 근거를 검토한 값만 사용한다.
- 로컬 사전에서 道는 토지만 일부 기존 fallback 코드는 화다. 어느 쪽을 읽느냐에 따라 추천이 바뀌는 경로는 허용하지 않는다.

**미완료:** 공개적으로 확인·재사용할 수 있는 글자별 자원오행 출처를 초기 목록 전체에 연결하지 못했다. 어느 사전이든 하나를 지목하면 바로 검증이 끝나는 문제가 아니다. 이 문서 승인은 특정 200자의 정확성을 승인하는 것이 아니다.

**2026-09-30 후속 확인 범위:** [기존 21자·24독음 대조](../research/2026-09-30-name-mvp-hanja-verification.md)와 [추가 5자](../research/2026-09-30-name-mvp-hanja-expansion.md)를 합쳐 26고유자·29자형–독음 쌍의 자료를 검토했다. 기존 21자는 실시간 법원 화면, 추가 5자는 2024 시행표 보존본으로 확인했으며 판본 차이는 보존한다. 26자 모두 §4.4의 강희 전사 기준 원획 근거가 있다. 오행 분류는 서비스 자체 해석이며 전통문헌 배속표 검증이 아니다. 일부 글자의 배속·뜻 보류와 명시적 제외를 유지하며 실제 적격 수는 위 보고서와 JSON을 따른다. 200자 목표는 미달이고, 원획이나 허용 독음 확인이 모든 글자의 추천 적격을 뜻하지 않는다.

### 4.4 원획수와 81수리의 자료 기준

**원획 자료 한 기준과 81수리 한 판본을 고정하고 실제로 대조한 범위만 제공**한다. 글자 획수와 수리 길흉표는 서로 다른 출처 필드로 둔다. 한자의 일반 필획 수를 원획 수로 자동 취급하거나, 부수 치환 상수만으로 모든 글자의 원획을 계산하지 않는다.

**원획 기준 채택(2026-09-30 후속):** 초기 정책 ID는 `kangxi-tongwen-entry-v1`이다. 康熙字典網上版의 정확한 표제자에 명시된 총획과 同文書局本 위치를 함께 기록한 값을 사용한다. [21자 획수 대조](../research/2026-09-30-name-mvp-original-strokes.md)는 웹 전사·편집 메타데이터 확인 수준이며 스캔 교감이나 한국 작명계의 통일 표준 인증이 아니다. 이 한계를 자료 버전에 남긴다. 원문 스캔 또는 다른 전사와 충돌하면 해당 글자의 수리를 보류하고 새 버전에서 해결한다. 현대 필획에서 부수 보정으로 값을 생성하거나 岳를 嶽으로 바꾸지 않는다. 이 정책을 채택한 수리 참고 풀이에서는 검토된 총획을 사용할 수 있으며, 한자 추천 적격과는 독립이다.

**2026-09-30 채택:** 熊崎健翁의 『運命の神秘 : 附録・撰名字引』(1930)을 수리 참고 풀이의 기준 판본으로 고정한다. [실제 원전 대조](../research/2026-09-30-name-mvp-suri-verification.md)에서 pp.46–50의 네 형태 산식·가획, pp.66–81의 81개 본문과 환원 설명을 확인했다. 검토는 AI의 자료 판독이며 전문가 교감이나 효능 검증이 아니다. 기존 코드의 등급표·산식이 이 판본과 같다는 승인이 아니다.

새 MVP는 위 대조 문서의 네 산식을 채택한다. 지격→원격, 인격→형격, 외격→이격, 총격→정격은 서비스의 용어 대응이다. 단성+두 글자의 외격은 `1+N2`, 단성+외자는 `2`, 복성+외자는 `S1+1`이며 기존 코드와 다르다. 복성+두 글자는 `S1+N2`다. 가획은 총격에 더하지 않는다. 기존 게임의 계산기는 이번 문서 변경으로 수정하지 않는다.

원전은 일률적 네 등급표가 아닌 조건부 산문이다. **MVP는 수리별 참고 설명만 제공하고 기존 대길/길/흉/대흉·점수·격명 표를 원전 인증값으로 내보내지 않는다.** 성별 편견·질병·죽음·인생 결과 단정은 채택하지 않는다. 연구 JSON의 원문 요약을 사용자 문구로 그대로 노출하지 않으며, 조건과 한계를 보존한 별도 문구 검토가 필요하다.

초기 제공 범위는 **원획 합산값 1~81**로 한정하고, 이보다 크면 해당 격의 참고 풀이만 미제공한다. 81은 독립 항목을 유지하며 1로 돌아간다는 원문의 설명을 덧붙인다. 원문에는 82→2·83→3과 80을 빼는 설명이 있지만 기존 `%81` 순환은 다르므로 재사용하지 않는다. 160 초과 반복 환원의 수학적 일반화는 초기 MVP에 필요하지 않아 보류한다. 0·음수·비정수는 유효 획수로 받지 않는다.

자료 대조 결과와 남은 항목:

1. 81행의 조건부 원문 설명과 위치는 대조 완료. 사용자용 참고 문구와 글자별 원획 판본 검토는 아직 필요하다. 미확인 자료를 ‘흉’ 기본값으로 채우지 않는다.
2. 단성·복성과 외자·두 글자 이름의 산식은 위 원전식으로 고정. 기존 `suri81.ts`의 네 분기를 그대로 복사하지 않는다.
3. 가획 +1은 원전 대조 완료. 합산값 81 초과는 초기 제공 범위 밖이며, `%81` 환산으로 성공 처리하지 않는다.
4. 기존 코드에 붙은 연령 구간·역경 대응·인생 단정은 이번 서비스에 자동 포함하지 않는다. 확인된 수와 참고 풀이만 제공한다.

이미 확정한 성씨 1~2글자·이름 1~2글자는 지원 길이의 상한이다. 길이 안에 들어와도 자료·산식이 확인되지 않으면 수리 풀이를 내지 않는다. 수리 미제공은 추천 이름의 실패나 낮은 등급을 뜻하지 않는다.

**제작 영향:** 원전 본문·산식 검토와 채택 정책 아래 26자의 원획 자료는 확보했다(기존 21자와 [추가 5자](../research/2026-09-30-name-mvp-hanja-expansion.md)). 나머지 글자와 사용자용 문구·계산 구현은 미완료이므로 아직 수리 기능을 출시 완료로 볼 수 없다. 제공 범위를 숨기거나 임의 표로 채우지 않는다. 수리 기능은 MVP에 유지한다.

## 5. 표기·순위·결과 상태

### 5.1 문자열 계약

- 한글 성씨·이름은 앞뒤 공백을 제거하고 NFC 정규화한 뒤 현대 한글 완성 음절만 허용한다. 내부 공백·기호·독립 자모를 자동 삭제하거나 음절로 추정하지 않는다. 길이는 정규화한 음절 수로 센다.
- 한자는 원문 Unicode 코드 포인트를 보존한다. NFC도 호환 한자를 다른 자형으로 바꿀 수 있으므로 한자에는 NFC·NFKC·단순 번체/간체 변환을 적용하지 않는다. 선택기는 자료의 자형–독음 식별자를 전달하고 서버가 실제 자형·독음을 대조한다. 이체자는 확인된 명시적 관계로만 연결하며 원형을 덮어쓰지 않는다.
- 보충 평면 한자는 UTF-16 코드 유닛 두 개를 글자 두 개로 세지 않는다. 이체자 선택자가 포함된 표기는 검증된 데이터 식별자가 있을 때만 지원하며 선택자를 조용히 제거하지 않는다. 지원하지 않는 자형은 미확인으로 남기고 한자 없이 부분 풀이할 수 있다.
- 최종 동점은 정규화한 이름 부분 한글 → 원형 한자열 순서로 Unicode 코드 포인트의 수치 사전순을 사용한다. 공통 접두사가 같으면 짧은 문자열이 먼저다. 지역·실행 환경에 따라 달라지는 locale 정렬과 임의 ID·입력 순서를 사용하지 않는다.
- 먼저 정렬하고 한글이 같은 후보 중 첫 한자 조합을 남긴다. 현재 이름 제외, 균형형 최대 3개 확정, 그 이름을 뺀 극대화형 최대 3개 확정, 노출 개수 적용 순서를 따른다. 동일 입력·버전·노출 설정이면 결과가 같다.

## 6. 명리 규칙·자료 납품과 출시 수용 조건

### 6.1 명리 규칙 묶음

규칙별로 식별자·버전·원문 판본/위치·서비스가 해석한 범위·필요 관측값·성립 조건·제외 조건·결론·다른 규칙과 겹칠 때의 처리·근거 출력·지원하지 않는 경우를 납품한다. 조건은 “뿌리가 충분하다” 같은 자연어만으로 끝내지 않고 입력 관측값으로 참/거짓/미확인을 결정할 수 있어야 한다. 원문에 없는 정량값을 원문 값으로 표시하지 않는다.

각 규칙에는 구현 결과에서 역산하지 않은 기대 판정과 근거, 성립 사례, 한 조건만 달라져 비성립하는 사례, 경계·충돌·미지원 사례가 필요하다. 실제 가능한 원국으로 구성하며 출생정보·역법 버전·네 기둥을 함께 남긴다. 실제 수행한 자료 대조자·일시·검토 범위와 이견을 기록하고, 하지 않은 전문가 검증을 표기하지 않는다. 확정할 근거가 부족한 규칙은 납품 후보 상태로 남긴다.

**2026-09-30 자료 대조 반영:** [명리 개별 조건표](../research/2026-09-30-name-mvp-bazi-condition-tables.md)에 5계절 프로필·12월지·4토월 사령, 12지 통근, 생극 관측, 조후·병약 6행, 통관 5종과 원문 긍정/음성 명식 3개를 작성했다. 토월의 문헌상 사령과 기존 지장간은 서로 다른 관측이며 자동 치환하지 않는다. 기존 출생시각 fixture 6개는 관측 대조에만 사용했고, 강약·용신 정답 검증으로 세지 않았다.

**남은 계산 조건:** 통근·생조·제약을 종합하는 최종 신강·신약 판정, 네 방법 전체의 적용/비적용·목표/역할을 닫는 지원 조건군, 특정 천간의 기능을 오행 추천으로 옮기는 검증, 다섯 오행 쌍별 구조 비교는 아직 미완료다. 부분 문헌 후보는 최종 허용 오행이 아니다. 자동 판정에 필요한 술어를 임의 점수로 채우지 않는다. 이는 단순 테스트 실행으로 끝나는 작업이 아니라 근거 있는 모델 결정·독립 기준 사례 대조·구현의 출시 의존성이다.

### 6.2 닫힌 지원 범위를 정하는 절차

1. 출처와 규칙을 확보한 조건군을 후보로 정한다. 범위는 일간·월지뿐 아니라 필요한 통근·노출·생조·제약·합충·특수 구조의 포함/제외 조건을 함께 쓴다. 특정 성공 명식 목록을 지원 범위로 삼지 않는다.
2. 범위 판정기가 어떤 입력도 지원·미지원·판단 불가 중 하나로 분류하도록 만든다. 제외 조건을 평가할 수 없으면 범위 안으로 넣지 않는다. 범위 안에서는 필요한 강약·방법별 적용 여부·구조 비교가 누락 없이 계산돼야 하며, 범위 밖에는 이유를 반환한다.
3. 양성·음성·경계 사례를 독립 기대값과 대조한다. 각 분기와 경계, 방법 충돌, 단독/공동 최강/비교 불가, 특정 천간, 합충, 특수 구조를 포함한다. 시간 모름은 절입·일계·지역 시각 보정을 반영한 가능한 완전 원국 집합과 그 구간의 포괄성까지 검증한다.
4. 지원 범위표와 별도로 대표 입력 묶음을 결과를 보기 전에 고정한다. 입력 날짜·월지·강약 조건·정확한 시각/모름·성씨 길이·분위기를 나눠 유형별 제공 수, 보류 이유, 데이터 부족, 처리 시간과 탐색 상한을 측정한다. 제공률을 높이려고 실패 사례를 사후 삭제하지 않는다.
5. 범위표, 검증 결과, 실제 제공/보류 분포, 모바일 대기시간 확인 결과를 출시 기록에 첨부한다. 현재는 이 산출물이 없으므로 제공률·성능 수치를 주장하지 않는다.

공개 MVP는 균형형·극대화형 각각 실제 지원 조건군에서 추천까지 성공하는 검증이 있어야 한다. 한 유형 또는 두 유형이 모든 입력에서 보류되는 엔진은 출시할 수 없다. 몇 개 시연 성공만으로도 통과시키지 않는다. 조건군 전체의 계약 검증과 사전 고정한 대표 입력의 결과를 함께 검토하고, 지원 범위를 안내할 수 있어야 한다. 제품에서 승인한 입력 범위를 몰래 축소해 성공률을 높이지 않으며, 명리 해석 미지원은 입력 거절과 구분한다.

### 6.3 한자·이름 데이터 묶음

추천 한자 자료는 각 자형–독음 쌍의 공식 허용 근거, 뜻 출처와 직접 작성한 설명, 자원오행 분류 근거/채택 이유, 필드별 검토 상태, 제외 사유, 자료의 버전·기준일·원본 위치·사용 조건을 포함한다. 원획은 별도 검토 필드다. 출처를 확보할 수 없는 행은 추천 목록에 넣지 않는다. 한자 독음별로 뜻·오행이 달라질 수 있는 자료는 충돌을 해소한 행만 납품한다.

별도 이름 자료는 정규화한 한글 이름, 자연스러움 검토 여부와 근거, 복수 분위기 태그, 정확히 일치하는 이름/전체 이름 제외 항목을 포함한다. 이 자료는 실행 시 AI로 채우지 않는다. 미검토는 후순위이며 미분류를 중성으로 바꾸지 않는다. 200자는 목표일 뿐 품질 통과 수치가 아니다. 실제 데이터 버전으로 모든 목표 오행과 분위기 선택에 대한 후보 분포·중복 제거 후 부족 사례를 보고하고, 부족을 가짜 한자·독음으로 메우지 않는다.

수리는 제공할 원획 자료와 81수 판본의 정확한 위치, 대조한 수의 목록, 지원하는 성씨/이름 길이별 산식, 가획·81 초과 처리의 확인 여부, 계산 예시를 납품한다. 확인되지 않은 행·산식은 미제공 범위표에 명시한다. 출시 시 수리 기능이 전부 비어 있으면 확인 범위 제공이라는 약속을 충족하지 못하므로 실제 제공 가능한 범위와 기준 사례가 있어야 한다.

### 6.4 최종 수용 확인

- 승인된 초성표와 무방향 상생 관계, 이웃 음절 비교, 순위·중복 제거가 동일 입력·버전에서 재현된다.
- 한자 누락·현재 이름 목록 밖·긴 이름·자료 충돌·호환 자형·보충 평면 문자를 각 계약대로 처리한다.
- 강약·상대 최강을 서로 복사하지 않고 방법 미지원과 비적용, 동률과 비교 불가, 처리 오류와 해석 보류를 구분한다.
- 시간 모름의 원국 후보 포괄성과 두 유형별 목표/허용 조합 합의를 확인하며 원본의 부분 상태를 유지한다.
- 지원 범위 안의 실제 추천과 범위 밖의 설명, 후보 부족, 수리 일부 미제공을 모두 확인한다. 숫자상 후보 개수를 맞추려고 조건을 완화하지 않는다.
