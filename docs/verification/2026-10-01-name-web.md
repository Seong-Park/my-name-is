# 프런트엔드 구현·검증 기록

대상: `C:/workspace/my-name-is/apps/name-web`, 2026-09-30~10-01. 기존 master와 기존 파일을 보존했고 커밋·배포·병합하지 않았다. MyLife 앱은 수정하지 않았다.

## 구현 범위

기존 저장소에는 제품 웹 앱/API가 없었다. 승인된 프런트 ADR에 맞춰 Next.js 앱을 추가하고 기존 지역 자료와 설치된 음력 달력 라이브러리를 재사용했다. 계산 패키지와 미검증 전체 한자 사전은 대체하거나 브라우저에 싣지 않았다.

CSS 토큰 → 공통 입력/버튼/선택/dialog → 화면 조합 → fetch/기록 연결 순으로 구현했다. 41개 프레임은 10개 화면 상태와 컴포넌트 상태로 모델링했다. 이름·출생정보를 URL에 넣지 않으며 공유는 서비스 루트 URL만 사용한다.

## 남은 연결·검증

1. 검토 완료 한자 검색 API와 승인 규칙 기반 분석·추천 API. UI 어댑터의 중첩 DTO/reasonCodes를 실제 서버 응답에 매핑.
2. DeepSeek 생성은 환경 변수 자리만 준비. 서명 영수증·익명 cookie·후보 재검증·Neon 비용 예약/정산·불확실 과금 처리·공급자 응답 검증 구현 후 연결. 이번 실행에서 실제 AI 요청/과금 없음.
3. Kakao 앱·공개 키·도메인 설정과 Android/iOS/PC 실제 공유 전송·취소 검증. 이번에는 클립보드 경로만 검증했고 메시지를 보내지 않음.
4. 실제 모바일 가상 키보드·safe area·스크린리더, 두 탭 동시 조작의 전체 브라우저 시나리오, 모든 실패 상태의 개별 시각 캡처는 미검증. 저장 충돌은 단위 검사, 같은 탭 동시 저장은 브라우저 검사로 구분.
5. 공개 배포 전 Next.js 보안 패치 적용. 확인 시 npm latest는 16.3.7이며 [공식 공지](https://nextjs.org/blog/upcoming-nextjs-security-release-september-2026)는 이 버전에 예정 보안 수정이 없다고 명시한다.

서버 미구현을 일반 ‘판정 보류’로 위장하거나 임의 이름으로 대신 표시하지 않는다. 개발 성공 흐름의 통과는 실서비스 추천/AI 계산 검증을 뜻하지 않는다.

## 후보 조합·정렬 서버 모듈 후속

- lib/server/naming.ts는 최종 판정 목표가 주어진 뒤의 PRD 기계적 계약을 구현한다. 균형형은 목표 한 글자 이상+명시 허용 집합, 극대화형은 목표 두 글자다. 목표 null이면 빈 후보이며 명리 판정기를 대신하지 않는다.
- 자연스러움→분위기→인접 발음 상극 수→한글/원형 한자 Unicode 코드포인트 순서. 현재 이름 제외, 동음 후보 하나, 균형형 최대 3개 확정 후 극대화형 중복 제외, 그다음 공개 개수 적용. 고정 후보/날짜 lookup을 사용하지 않는다.
