## 채택한 제품 정책과 기대값

<a id="p1"></a>

### P1 — 지장간은 membership·role을 보존하고 수치 배분은 사용하지 않기 (권고)

일간 기준 통근·투간·격국 후보에 사용할 상시 지장간 목록이다. **본기=main, 중기=middle, 여기=residual은 아래 고정 role 지정**이며 월 안에서 어느 날 사령하는지, 강약 점수 순위, 점유 확률을 뜻하지 않는다. role은 원문 목록에 대한 서비스 정규화 제안이다.

| 지지 | main | middle | residual |
| --- | --- | --- | --- |
| 子 | 癸 | 없음 | 없음 |
| 丑 | 己 | 辛 | 癸 |
| 寅 | 甲 | 丙 | 戊 |
| 卯 | 乙 | 없음 | 없음 |
| 辰 | 戊 | 癸 | 乙 |
| 巳 | 丙 | 庚 | 戊 |
| 午 | 丁 | 己 | 없음 |
| 未 | 己 | 乙 | 丁 |
| 申 | 庚 | 壬 | 戊 |
| 酉 | 辛 | 없음 | 없음 |
| 戌 | 戊 | 丁 | 辛 |
| 亥 | 壬 | 甲 | 없음 |

- `weight: null`은 미배분이다. 단위·합계는 해당 없음이며 0이나 합계 1/30/100으로 해석하지 않는다. Task 8은 모든 항목 null을 검사한다. 수치 정책을 나중에 도입하면 별도 버전과 단위·합계 테스트가 필요하다.
- 기존 `core-engine/constants/saju.ts`는 子에 壬10/癸20, 寅에 戊7/丙7/甲16 등을 저장한다. 원문 人元司事의 시간별 배분과 동일한지 검증 없이 복사하지 않는다. 기존 게임은 변경하지 않는다.
- 대안: 특정 판본의 사령 일수표를 별도 데이터로 채택. membership과 별도 모델·날짜 조건이 필요하다. 임의 60/30/10 또는 기존 30일표를 강약 기여율로 사용하는 안은 권고하지 않는다.
- 구분 예: 권고안의 子에는 癸만 있고 壬은 없다. 寅에는 甲/丙/戊가 있고 모든 weight는 null이다.

<a id="p2"></a>

### P2 — 십이운성은 양간 순행·음간 역행, 토간은 화간을 따르기 (권고)

장생 시작: 甲亥, 乙午, 丙寅, 丁酉, 戊寅, 己酉, 庚巳, 辛子, 壬申, 癸卯. 단계 순서: 長生→沐浴→冠帶→建祿→帝旺→衰→病→死→墓→絶→胎→養. 원문 臨官은 M1의 建祿, 絕은 絶로 정규화한다.

예: 甲子=沐浴, 乙巳=沐浴, 戊寅=長生, 己申=沐浴. 토를 수와 같이 놓는 대안이면 戊申=長生 등 결과가 달라진다. 십이운성을 종합 강약 등급이나 점수로 자동 변환하지 않는다.

<a id="p3"></a>

### P3 — 신살 v1은 네 종류를 연지 기준으로 탐지하기 (권고)

연지의 삼합군을 기준으로 다른 원국 위치(월·일·시)의 지지를 비교한다. 기준 위치 자신을 대상으로 재사용하지 않는다. 기준/대상 위치와 글자를 근거에 보존하고, 미상 시주는 평가 불가로 표시한다. 등장 여부만 계산하며 길흉·활성도·인물 평가를 출력하지 않는다. **연지 기준 선택은 원문의 유일한 해석이라는 주장이 아닌 서비스 정책**이다.

| 기준 연지 그룹 | 역마 | 도화(咸池) | 화개 | 장성 |
| --- | --- | --- | --- | --- |
| 申子辰 | 寅 | 酉 | 辰 | 子 |
| 寅午戌 | 申 | 卯 | 戌 | 午 |
| 巳酉丑 | 亥 | 午 | 丑 | 酉 |
| 亥卯未 | 巳 | 子 | 未 | 卯 |

예: 연지 子·일지 寅→역마 탐지; 연지 子·일지 酉→도화 탐지. 일지 寅만으로 연지의 역마를 역방향 검사하지 않는다. 대안은 연지·일지를 별도 ruleCode로 병행하는 방식이며 탐지 결과가 늘어난다. 나머지 신살은 `unsupported`로 명시하고 `detected:false`로 가장하지 않는다. 기존 RPG 12신살/스탯 보너스는 신규 규칙 근거가 아니다.

<a id="p4"></a>

### P4 — 파는 확인한 원문의 4쌍 채택 (권고)

卯午·丑辰·子酉·未戌을 채택하고 寅亥·巳申은 제외한다. 확인한 四庫本 卷03의 破煞는 네 쌍을 열거하고 寅申巳亥는 취하지 않는다고 적는다. 대안은 통용 6쌍을 별도 MyLife 제품 확장으로 채택하는 것이며, 이를 이 원문의 직접 전사라고 표시할 수 없다. 예: 子酉는 파, 寅亥는 육합으로 남고 파로는 출력하지 않는다. Task 9의 파 fixture 수는 이 선택에 따라 달라진다.

## 독립 기대값·후속 검증

`packages/bazi-rules/tests/fixtures/rules-reference.json`은 원문과 위 표를 보고 따로 입력한 **Task 7 표본 fixture 38개**다. 구현표를 import하거나 실행해 생성하지 않는다. sourceIds·원문 위치·ruleId·정책 상태를 행마다 보존한다. 기존 proposed 22개 행은 P1~P4 채택 기록과 함께 adopted로 갱신했다. YHZP-HS의 기계 출처 URL은 상세 조사에서 교차 확인한 [東里書齋 원문](https://www.donglishuzhai.net/chapter/12808.html)이며, 영인본 쪽 번호의 육안 교감은 미완료다.

출처 누락 검사는 출처 존재·위치·참조 무결성을 검사할 뿐 원문 의미의 정확성을 증명하지 않는다. Task 8에서 10간/12지/60갑자/지장간 전 항목과 십성 100개, Task 9에서 관계 전체·십이운성 120개·채택 신살 전체로 수기 기대값을 확장·대조한다. M2 완료는 Task 10까지 보류한다.

- basic-reference.json은 HKO 순서와 SMMT 속성의 독립 기대값, ten-gods-reference.json은 SMMT-05의 생극·음양 정의를 100셀로 수작업 전개한 기대값이다. 후자는 원전에 10×10 현대 코드표가 그대로 있다는 주장이 아니다. 구현표·기존 core-engine·계산 함수를 사용해 fixture를 생성하지 않았다.
- 십성은 동오행: 같은 음양 비견/다른 음양 겁재, 내가 생함: 식신/상관, 내가 극함: 편재/정재, 나를 극함: 칠살/정관, 나를 생함: 편인/정인으로 코드 정규화한다. 원전의 시대별 별칭·선호 해석과 분리한다.
- 지장간은 채택한 P1 역할표 전체를 비교하고 가중치가 모두 null임을 검사한다. 지장간에 壬子·甲卯·庚酉 같은 사령표 잔여 항목을 추가하지 않았다.
- readonly는 TypeScript 소비자 계약이며 JavaScript Object.freeze나 런타임 입력 검증을 뜻하지 않는다. 날짜 계산·합화·관계·십이운성·신살 표는 이번 구현 범위 밖이다. M2 완료는 Task 10이다.

## Task 9 구현 반영 (2026-09-23)

관계 48행(천간합 5·지지 43), P2 십이운성 120셀, P3 신살 4종의 16개 삼합국 대응을 정적 표로 공개했다. 관계는 각각 ruleCode/members/sourceIds를 갖고, 십이운성은 공통 출처 메타데이터를 갖는다. 형은 쌍과 완전 삼형을 별도 행으로 보존하며 원문 방향을 남긴다. 자형은 동일 지지라도 서로 다른 위치가 필요하다. unordered/distinctPositions는 후속 탐지기가 따라야 할 데이터 계약이다. 합화 성립은 전부 미평가다.

P4의 파 4쌍을 대조하고 寅亥·巳申을 파에 추가하지 않았다. 신살의 연지 기준과 월일시지 대상은 채택한 제품 범위이며 전통의 유일한 해석이라는 뜻이 아니다. 전체 12신살·천을귀인·양인·공망 등 지원 4종 밖은 unsupported다. 시간 미상은 unavailable로 처리해야 하며 false로 대체하지 않는다. 테스트 fixture는 구현표에서 읽거나 생성하지 않고 별도로 작성했다. 기존 원전 전사 검증 수준과 권리 고지는 그대로 적용된다. M2 전체 완료는 Task 10 이후 판단한다.
